# Своя оболочка для Яндекс Станции Макс

Станция Макс — это Android 9 (`yandexstation_2`, `arm64-v8a`) с залоченным загрузчиком. Root нет, каталога `/data/opt/yandex-station` нет, пакет для [Станции 2 и Мини 2](https://github.com/YanchikAmb/yse-home) сюда не ставится и ставиться не должен.

Вместо этого на колонку ставится обычное приложение `com.yse.station`. Оно само держит микрофон, страницу на порту 18080, часы и кольцо. Тяжёлую работу по-прежнему делает домашний сервер из репозитория [yse-home](https://github.com/YanchikAmb/yse-home): распознавание, ответы, музыка, Home Assistant.

Это только приложение. Сервер, DNS и установка на колонку — сервис yse-home. Колонку добавляют на его странице, модель «Макс». Сюда попадают правки самого APK и подстановка `HOST` / `BASE` под тот сервис.

Готового APK в репозитории нет. Адрес сервера в собранное приложение пишет сервис yse-home: файл `files/server.txt`, первая строка — IP, вторая — `BASE`. Константы в `Web.java` используются, только если этого файла нет.

## Что получится

- Страница колонки: `http://IP_колонки:18080/`. С неё выбираются слово, распознавание, нейросеть, голос, будильники, музыка, кольцо и Wi‑Fi.
- Слово на выбор. «Джарвис» считается на самой колонке или на сервере. «Алиса» и «Яндекс» — заводскими моделями Яндекса, но внутри нашего процесса. Дальше фраза идёт в то распознавание, ту нейросеть и тот голос, которые выбраны на странице. В облако Алисы диалог не уходит.
- Команды дома через Home Assistant, музыка Яндекса, будильники, BLE-датчики в MQTT.
- Часы на матрице и кольцо остаются нашими, картинка по HDMI не перекрывается.

## Чего делать нельзя

Это не советы, а способы сломать колонку или вернуть её штатной Алисе.

- Не разблокировать загрузчик и не писать в boot и recovery.
- Не отключать пакет `com.yandex.io.sdk`. Без него пропадает звуковой тракт. Микрофон у него только отзывается: `RECORD_AUDIO` в deny и `pm revoke`. Сам пакет остаётся запущенным.
- Не включать и не запускать `com.yandex.tv.alice`. Это приложение забирает часы, кольцо и диалог. Оно должно остаться выключенным пользователем (`pm disable-user`).
- Не ставить на Макс оболочку Станции 2 (`install/yse_station_setup.py speaker`). Ей нужен root и другой звуковой контур.

## Что нужно

| Что | Зачем |
| --- | --- |
| Яндекс Станция Макс в вашей сети, ADB по TCP порт 5555 | Поставить приложение. Root не нужен |
| Сервер с уже поднятым [yse-home](https://github.com/YanchikAmb/yse-home) | Распознавание, ответы, музыка. Для Макса в окружении колонки `YSE_PLAY=http`: сервер на колонку по SSH не ходит |
| Home Assistant | Необязательно. Без него нет команд дома |
| Компьютер с `adb` | Установка APK |

Приложение стучится на сервер по адресу из `files/server.txt`. Его пишет установка колонки в yse-home из `YSE_VOICE_HOST` и `YSE_VOICE_BASE`. Если файла нет, берутся константы `src/com/yse/station/Web.java`:

| Константа | Куда | Запасное значение |
| --- | --- | --- |
| `HOST` | IP сервера голоса | `192.0.2.10` |
| `BASE` | первый порт блока колонки | `18805` |

Порты от `BASE`:

| Порт | Кто слушает | Что по нему идёт |
| --- | --- | --- |
| `BASE` | `yse-wake` | UDP: звук микрофона и пакеты `YSEMODE` / `YSEWAKE` |
| `BASE + 1` | `yse-music` | HTTP, Яндекс Музыка |
| `BASE + 3` | `yse-talk` | HTTP, распознанная фраза и ответ |
| `BASE + 5` | `yse-talk` | TCP, сырая фраза после слова |

Собирать APK под каждый дом не нужно: после установки сервис записывает свой адрес. Адрес MQTT для BLE меняется на странице, в код его зашивать не нужно.

## Поставить APK

Колонка должна отвечать на `adb connect IP:5555`. Дальше с компьютера, где есть `adb`:

```
adb connect IP:5555
adb -s IP:5555 install -r -d -g station.apk
adb -s IP:5555 shell cmd appops set com.yandex.io.sdk RECORD_AUDIO deny
adb -s IP:5555 shell pm revoke com.yandex.io.sdk android.permission.RECORD_AUDIO
adb -s IP:5555 shell pm disable-user --user 0 com.yandex.tv.alice
adb -s IP:5555 shell appops set com.yse.station WRITE_SETTINGS allow
adb -s IP:5555 shell pm grant com.yse.station android.permission.READ_LOGS
adb -s IP:5555 shell pm grant com.yse.station android.permission.ACCESS_FINE_LOCATION
adb -s IP:5555 shell pm grant com.yse.station android.permission.ACCESS_COARSE_LOCATION
adb -s IP:5555 shell settings put secure assistant com.yse.station/com.yse.station.VoiceAssist
adb -s IP:5555 shell settings put secure voice_interaction_service com.yse.station/com.yse.station.VoiceAssist
adb -s IP:5555 shell am start-foreground-service -n com.yse.station/.Web
```

`install -g` выдаёт опасные права сразу, в том числе геолокацию: без неё Android 9 не отдаёт список Wi‑Fi и BLE. Кнопку Home слать не нужно: она уводит телевизор в лаунчер.

Откройте `http://IP:18080/`. Через несколько секунд после старта в статусе у заводского слова должна появиться строка, начинающаяся с «штатное». Пока её нет, слово ещё грузится.

Проверка, что микрофон не вернулся Яндексу и Алиса не включилась:

```
adb -s IP:5555 shell dumpsys package com.yandex.tv.alice | grep -m1 enabled=
adb -s IP:5555 shell cmd appops get com.yandex.io.sdk RECORD_AUDIO
```

Ожидается `enabled=3` и `deny`.

## Слово пробуждения

На странице четыре значения. Фраза, голос и нейросеть от выбора слова не зависят.

| Значение | Где ищется слово |
| --- | --- |
| `джарвис-локально` | На колонке, модель `ru_jarvis_mww.tflite`. Порог, который передаётся в модель, `0.74`. Ниже ловит шум, выше не слышит с двух метров |
| `джарвис` | На сервере, `yse-wake`. Колонка только шлёт звук |
| `алиса` | На колонке, заводская модель `activation/alisa` (порог модели 0.44) |
| `яндекс` | На колонке, заводская модель `activation/yandex` (порог модели 0.93, слово короткое и модель строгая) |

Пока выбраны «Джарвис локально», «Алиса» или «Яндекс», колонка раз в три секунды шлёт `YSEMODE`. Серверная модель «джарвис» в это время колонку не будит. Срабатывание — пакет `YSEWAKE`, сигнал и запись фразы.

После собственной речи колонка 5 секунд не реагирует на слово, и между двумя «Алиса» / «Яндекс» не меньше 2,5 секунды.

### Как услышано «Алиса», не отдавая микрофон

Модели лежат в системном `/system/priv-app/ServicesIosdk/ServicesIosdk.apk`, каталоги `assets/quark/spotter_models/activation/alisa` и `.../yandex`. Библиотеки из того же APK: `libquasar_daemons.so`, `libtflite.so`, `libglib.so`, `libiconv.so`. Приложение копирует их в свой каталог и открывает споттер само. Процесс Алисы при этом не запускается.

Два флага в `flags.txt` модели перед открытием переписываются. Мы кормим споттер одним уже очищенным каналом 16 кГц, а не сырым массивом:

- `raw-mic-channels 0`
- `freq-filter-enabled false`

Имя устройства, с которым модель открывается на Максе: `Yandex Station_2`.

У этих моделей включён флаг `new-unhandled-nbytes`. Возврат `submit` — это сколько байт споттер **не** забрал. Ноль значит, что кусок принят целиком. Если ноль считать ошибкой и подавать тот же буфер снова, слово не сработает никогда: споттер «заряжен», микрофон живой, событий нет. На Станции 2 контракт другой, там возврат — число забранных байт. См. [wake-contract.md](https://github.com/YanchikAmb/yse-home/blob/main/speaker/docs/wake-contract.md) того репозитория и не переносите его на Макс буквально.

Дальше читаются события. Код события `2` и строка `<speech_started>` — это начало речи, её пропускаем. Следующее событие `2` — само слово.

Звук в споттер — первый калиброванный канал VQE, 48 кГц, ужатый в 16 кГц усреднением по три отсчёта. В запись фразы на сервер тот же канал кладётся без усиления: усиление на колонке загоняет распознавание голоса в клиппинг. Тишину добирает сервер, отдельно на каждом кадре.

### Если слово есть, а ответа нет

Пустая короткая фраза после сигнала — это эхо самого сигнала. Сервер с `YSE_QUIET_RMS` (на рабочей колонке 500) такую фразу глотает и молчит. Настоящая фраза приходит следом, вторым прослушиванием.

Если фраза распознана, а колонка всё равно молчит, смотрите журнал `yse-talk`. Частый случай: вопрос про погоду, а у сущности погоды в Home Assistant температура `null`. Ответ не должен падать с исключением на `None`, иначе соединение обрывается и колонка не произносит ничего. Нет числа — колонка говорит, что данных о погоде нет.

## Wi‑Fi, когда кабель уже воткнут

Кнопка «Подключить» на странице сохраняет сеть через `WifiManager`. Пока колонка сидит на Ethernet, Android не держит запрос на Wi‑Fi: кабель уже удовлетворяет сеть по умолчанию. В логе это `CMD_START_CONNECT but no requests and not connected, bailing`. Сеть в списке сохранённых есть, ассоциации нет.

Приложение перед включением сети вызывает `ConnectivityManager.requestNetwork` с транспортом `WIFI` (право `CHANGE_NETWORK_STATE`) и держит этот запрос, в том числе после перезагрузки. Кабель при этом не выдёргивается. Кнопка ждёт до 12 секунд и пишет «В сети …» либо «не подключилась, проверьте пароль».

Пароль с кавычкой `"` страница не принимает. Сеть без пароля сохраняется как открытая.

## Что переживает перезагрузку

- Настройки страницы, файл `settings.json` в каталоге приложения. Их поднимает `Boot` по `BOOT_COMPLETED`.
- Скопированные библиотеки споттера и модели.
- `pm disable-user` для `com.yandex.tv.alice` и запрет микрофона у `com.yandex.io.sdk`.
- Сохранённая Wi‑Fi-сеть. Запрос на Wi‑Fi приложение выставляет снова при старте, поэтому сеть поднимается и при воткнутом кабеле.

Первые секунды после включения слово ещё молчит: споттер копируется и открывается.

## Собрать самому

Нужны Linux, JDK 8, Android SDK platform 28, build-tools 30.0.3 и NDK r21e. Модель слова `ru_jarvis_mww.tflite` берётся из обучения в репозитории `yse-home` (каталог `speaker`). Исходники TensorFlow Lite Micro — `speaker/third_party`.

`libjarvismww.so` линкуется с `-static-libstdc++`. На Android 9 нет системного `libc++_shared.so`, без этого флага библиотека не загрузится.

Порядок такой же, как у обычного старого APK без Gradle: `javac` против `android.jar` платформы 28, `d8 --min-api 26`, `aapt package` с `AndroidManifest.xml` и `res/`, в zip дописываются `classes.dex`, `assets/panel.html` и `lib/arm64-v8a/*.so`, затем `zipalign` и `apksigner`. Модель кладётся в APK методом `ZIP_STORED`.

Часы — framebuffer `/dev/graphics/fb4`, яркость `/sys/class/backlight/fb4/brightness` (потолок на этой плате 200). Кольцо — `/dev/graphics/fb5`. В покое матрицу рисует штатный контроллер часов. Приложение рисует её само, только пока слушает, думает или говорит.

Микрофон: `AudioRecord` на 16 каналов, 48 кГц, системный эффект `YandexVQE`. Для слова и фразы берётся канал 1, это калиброванный выход шумодава.

## Если что-то не так

| Что видно | Куда смотреть |
| --- | --- |
| Страница не открывается | `adb shell am start-foreground-service -n com.yse.station/.Web`, затем `curl http://IP:18080/api/status` |
| «Алиса» не срабатывает, в статусе нет «штатное» | споттер ещё открывается или не нашёл библиотеки в `ServicesIosdk.apk` |
| «штатное» есть, событий нет | в подаче звука ноль от `submit` обработан как отказ. Ноль значит «весь кусок принят» |
| Слово сработало, тишина | журнал `yse-talk`: пустая фраза или исключение в ответе |
| Wi‑Fi сохраняется и не подключается | в logcat `no requests and not connected`. Запрос `TRANSPORT_WIFI` должен жить, пока кабель воткнут |
| Пропали часы или кольцо | включилась `com.yandex.tv.alice`. Её снова `pm disable-user` |
| Нет звука микрофона совсем | пакет `com.yandex.io.sdk` выключен. Его нужно включить обратно и заново запретить только `RECORD_AUDIO` |
